# 2 · Idea (10 min)

**Deck section:** 02 My story with AI · **Output:** `IDEA.md` in your workspace

> **Slide recap:** a confident answer can be wrong. Models agree with you, reverse when pushed, and answer ambiguous questions differently. Stop trusting, start testing, and give the model the context its next step needs. A precise idea is the first piece of that context.

## Checkpoint

1. Create a workspace folder for this workshop, for example `~/octocode-workshop-notes`. Every later practice writes its files here.
2. Pick something small that you would use every week: an MCP server, a skill, or a feature for Octocode.
3. Create `IDEA.md` with these four lines:

   ```markdown
   # Idea
   Problem:      <who has which pain>
   What I build: <one sentence, for example "an MCP server that answers X">
   Done when:    <one observable check, for example "the agent answers X with a cited file:line">
   Out of scope: <what you will not do today>
   ```

✅ **Done when** all four lines are filled in, and a peer could run the **Done when** check without asking you a question.

## Go further

### A. Get the Octocode skills

Practices 4 and 5 use the Octocode skills. Install them for your agent (replace `claude` with your platform: `pi`, `cursor`, `codex`, `opencode`, `copilot`, `gemini`, or `all`):

```bash
npx octocode skill install --all --platform claude
npx octocode skill check
```

### B. Keep the source at hand

Clone the repository to read the skill files, docs, and source directly:

```bash
git clone https://github.com/bgauryy/octocode.git
```
