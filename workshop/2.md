# Workshop 2 · Idea (10 min)

**From the slides (My story with AI):** a confident answer can be wrong. Models agree with you (sycophancy), reverse their answer when pushed, and give different answers to an ambiguous question. The lesson: stop trusting and start testing, and give the model the context its next step needs (context engineering). A precise idea is the first piece of that context.

## Live checkpoint

In 10 minutes, complete **B**: write the four lines of `IDEA.md` for a small idea. Make “Done when” something a peer can observe. Installing all skills in **A** is preparation or an optional extension; use the agent you already set up.

### A. Get the Octocode skills locally

Either clone the repo, so the skills, docs and source are next to you:

```bash
git clone https://github.com/bgauryy/octocode.git
```

Or install all the skills:

```bash
npx octocode skill install --all --platform claude --global
# --platform: pi, cursor, claude, codex, opencode, copilot, gemini, all
npx octocode skill check     # verify
```

### B. Create a workspace and write `IDEA.md`

Create a local folder (your workspace) and add `IDEA.md`. The idea should be something you want to develop: an MCP, a skill, a feature, a platform, or even a feature for Octocode.

Think of a tool that would help you daily, or something you want to research how to build.

**Hints:**

- Define which problem you want to solve.
- Define what you expect it to be (e.g. "an MCP that helps me XYZ").
- Keep it small enough to build in the workshop.

```markdown
# Idea
Problem:      <who has which pain>
What I build: <one sentence, e.g. "an MCP that helps me XYZ">
Done when:    <one observable check, e.g. "the agent answers X with a cited file:line">
Out of scope: <what I will NOT do today>
```

✅ **Done when** `IDEA.md` has all four lines and its success check can be tested.
