# Workshop 3 · Planning (15 min)

**From the slides (Octocode V1):** MCP connects agents to tool servers. A server describes itself in three layers of text the model reads before any call: server instructions, tool definitions (description and schemas) and annotations. Octocode chose a search loop over RAG: find the repo (`ghSearchRepo`), find the place in it (`ghSearchCode`, `ghStructure`), then read the file at that `commitSha` (`ghGetFileContent`), and cite the lines. Package search jumps from a package name to its repository, and a search returns path + line, not the whole file; the fetch then reads only that window.

### A. Ask your agent to plan the idea

```text
Read IDEA.md and write a plan to build it: the approach, the main components, and an ordered task list.
```

Check the result: is the scope realistic? Is anything guessed (an API, a library, a pattern)?

### B. Improve the plan with Octocode on GitHub

```text
Use the Octocode tools on GitHub to find best practices and the most up-to-date recommended approaches
for this plan: how popular open-source projects implement it, which package versions are current,
and which recent issues or PRs change how it should be done. Cite file:line, versions and PRs.
Then compare with your first plan: what changed, and why?
```

Check whether the plan improved; you can ask the agent to show the differences.

✅ **Done when** you have a plan where the key decisions cite GitHub evidence, and you know what the research changed.
