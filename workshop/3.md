# 3 · One researched decision (10 min)

**Deck section:** 03 MCP and Octocode beginning · **Output:** one cited decision in your notes

> **Slide recap:** an MCP server describes itself to the model through instructions, tool definitions, and annotations. Octocode uses a search loop instead of RAG: it finds the repository (`ghSearchRepo`), finds the place (`ghSearchCode`, `ghStructure`), reads only that window at a `commitSha` (`ghGetFileContent`), and cites the lines.

## Checkpoint

1. Pick **one** decision in `IDEA.md` that depends on how something is really built.
2. Ask Octocode to find one repository that solves it, read the source, and cite the `file:line`.
3. Write one sentence: does the evidence change your plan, or confirm it?

✅ **Done when** the decision has a citation and a written change or confirmation.

## Go further

### A. Plan the idea

```text
Read IDEA.md and write a plan to build it: the approach, the main components, and an ordered task list.
```

Check the result. Is the scope realistic? Is any API, library, or pattern guessed?

### B. Check the plan against current practice

```text
Use Octocode to check this plan against current practice: how open-source projects implement
it, which package versions are current, and which recent issues or PRs change the approach.
Cite file:line, versions, and PRs. Then list what changed from the first plan, and why.
```
