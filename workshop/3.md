# 3 · One researched decision (10 min)

> **Slide recap:** an MCP server describes itself to the model through instructions, tool definitions, and annotations. Octocode uses a search loop instead of RAG: find the repo (`ghSearchRepo`), find the place (`ghSearchCode`, `ghStructure`), read only that window at a `commitSha` (`ghGetFileContent`), and cite the lines.

## Checkpoint

1. Pick **one** decision in `IDEA.md` that depends on how something is really built.
2. Ask the Octocode MCP to find one repository that does it, read the source, and cite the `file:line`.
3. Write one sentence: does the evidence change or confirm your plan?

✅ **Done when** the decision has a citation and a written change or confirmation.

## Go further

### A. Plan the idea

```text
Read IDEA.md and write a plan to build it: the approach, the main components, and an ordered task list.
```

Check the result: is the scope realistic? Is any API, library, or pattern guessed?

### B. Improve the plan with the Octocode MCP

```text
Use the Octocode MCP to check this plan against current practice: how popular open-source
projects implement it, which package versions are current, and which recent issues or PRs
change the approach. Cite file:line, versions, and PRs. Then list what changed from the first plan, and why.
```
