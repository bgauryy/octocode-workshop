# Workshop 4 · Research, RFC, build and review (35 min)

**From the slides (Octocode V2):** the same research flow runs on local code (`structureSearch`, `localSearch`, `localFetch`), and LSP/AST find the symbol you mean rather than every text match. Skills package repeatable workflows: MCP provides the actions, skills decide how to use them. API keys go in `~/.octocode/.env`, feature settings in `~/.octocode/.octocoderc` (which never holds GitHub tokens: sign in with `octocode auth login` or `gh auth login`); skills save their output in the workspace `.octocode/<skill>/`. Research Driven Development (RDD): plan, research and implement, with a verifier checking each step.

### A. Add a research key (one or all; each has a free tier)

Add **at least one** web search key for the brainstorming skill (more keys give better coverage). Free tiers are enough:

- Tavily: <https://app.tavily.com/>
- Serper: <https://serper.dev/>
- Exa: <https://dashboard.exa.ai/>

Put them in `~/.octocode/.env` (or `$OCTOCODE_HOME/.env` if you set that variable). Do **not** put them in the skill folder or your repo:

```bash
TAVILY_API_KEY=tvly-...
SERPER_API_KEY=...
EXA_API_KEY=...
```

Or set a key without leaving it in your shell history: `npx octocode config set TAVILY_API_KEY --stdin`.

Check the keys:

```bash
npx octocode config check TAVILY_API_KEY          # exit 0 when set; never prints the value
npx octocode skill check octocode-brainstorming   # skill installed + env readiness for all three keys
```

Both commands check only that a key is **set**, not that the provider accepts it. Details: [brainstorming skill, configuration](https://github.com/bgauryy/octocode/tree/main/skills/octocode-brainstorming#configuration--web-search-keys).

### B. Brainstorm: `octocode-brainstorming`

```text
Use octocode-brainstorming: what are the best practices and ideas for <my MCP / tool>?
Which features do similar projects have, which do users ask for in their issues, and which can I skip?
Cite every claim.
```

### C. Plan: `octocode-rfc-generator`

```text
Use octocode-rfc-generator to improve my plan into RFC.md, using IDEA.md, the plan and the brainstorm.
When a question is open, research it with the Octocode tools instead of guessing.
```

### D. Implement the RFC (`octocode-architect` helps)

Implement the RFC one task at a time. Use `octocode-architect` for boundaries, data flow and change impact. When you are unsure how to code a step, ask Octocode how real projects do it and keep the citation.

### E. Critique: `octocode-roast`

Use `octocode-roast` to find issues in the current implementation, ranked by impact with the code behind each one. Then fix them.

### F. Clean up: `octocode-clean-agentic-code`

Use `octocode-clean-agentic-code` to check the code for AI slop: dead paths, duplicates, needless wrappers. It removes only proven redundancy and verifies that behavior did not change.

✅ **Done when** `config check` reports a key as set, `RFC.md` exists with cited decisions, the RFC's "done when" check passes, and the roast and cleanup findings are fixed or written down.
