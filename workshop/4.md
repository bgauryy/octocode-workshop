# 4 · Short RFC and one build step (15 min)

**Deck section:** 05 Octocode V2 · **Output:** `RFC.md` and one implemented step, with its check

> **Slide recap:** the same research loop runs on local code (`structureSearch`, `localSearch`, `localFetch`), and LSP and AST find the symbol you mean, not every text match. MCP provides the actions; skills decide how to use them. Research Driven Development: plan, research, implement, and verify each step.

## Checkpoint

1. Write a short `RFC.md` from your practice 3 citation. Include the problem, the approach, one implementation step, and the check for that step.
2. Implement only that step.
3. Run its check and write down the result.

✅ **Done when** `RFC.md` cites the decision and the step passes its check. If the step is blocked, write the blocker and the next command you would run.

## Go further

Run these skills in order. Each one saves its output under your workspace at `.octocode/<skill>/`.

| Step | Skill | Ask for |
|---|---|---|
| A | `octocode-brainstorming` | Best practices for your tool, features similar projects have, what users ask for in issues, and what to skip. Cite every claim. Needs a web search key (see below). |
| B | `octocode-rfc-generator` | An `RFC.md` built from `IDEA.md`, the plan, and the brainstorm. It researches open questions instead of guessing. |
| C | `octocode-architect` | Boundaries, data flow, and change impact while you implement the RFC one task at a time. |
| D | `octocode-roast` | Issues in the implementation, ranked by impact, with the code behind each. Then fix them. |
| E | `octocode-clean-agentic-code` | Dead paths, duplicates, and needless wrappers, removed without changing behavior. |

### Add a web search key for brainstorming

`octocode-brainstorming` needs at least one web search key. Free tiers are enough: [Tavily](https://app.tavily.com/), [Serper](https://serper.dev/), or [Exa](https://dashboard.exa.ai/).

1. Store the key in `~/.octocode/.env`, not in the repository or the skill folder:

   ```bash
   touch ~/.octocode/.env     # creates the file if it is missing
   # open ~/.octocode/.env in your editor and add one line:
   # TAVILY_API_KEY=<your key>
   ```

2. Check that Octocode reads the configuration:

   ```bash
   npx octocode status --json
   ```

3. Check the brainstorming key from the skill folder. The script exits with `0` when the key is set and `1` when it is missing. It never prints the key value:

   ```bash
   node scripts/tavily-search.mjs --check
   ```

The checks confirm that a key is set. They do not confirm that the provider accepts it. See the [`octocode-brainstorming` skill](https://github.com/bgauryy/octocode/tree/main/skills/octocode-brainstorming) for the full configuration.
