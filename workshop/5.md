# Workshop 5 · Prompts, benchmark, skill and docs (25 min)

**From the slides (Octocode V3):** Octocode runs as a CLI without MCP and on a Rust engine; `clasify` asks a judge model (Jev) to score candidate files, so the agent doesn't read them all, but a score is not a citation: read the source before you claim. Give the critic a fresh context: the agent writes a reflection, strong models build, and a small fresh model explains the result cold so you can see where it misreads. Benchmark loop: measure, critique, change, repeat. A benchmark can fool its author: questions you tuned on are no longer clean, so keep a held-out set.

### A. Review the agentic flow: `octocode-agentic-prompts`

If you built an agentic solution (e.g. an MCP), use `octocode-agentic-prompts` to check possible improvements in the agentic flow: instructions, tool descriptions, schemas and results. **Don't fix anything yet**; just collect the findings.

### B. Benchmark: `octocode-eval-benchmark`

- Find **10 questions** you can benchmark your solution with. Mix easy and hard ones.
- Check that the questions are not overfitting: write them before you tune, and keep some you never tune against.
- Create the benchmark structure using `octocode-eval-benchmark` (baseline, dev cases, held-out set).

### C. Improve against the benchmark

Tell the agent to improve the benchmark result with a better implementation and better prompts (use the findings from **A**). Find ways to improve, then keep or revert each change **based on the numbers**, not on how it feels.

### D. Add a local skill: `octocode-skills`

Use `octocode-skills` to add a local skill for your project (for example, the workflow you repeated today). Write the trigger (the `description`) first: a skill the agent never loads does nothing.

### E. Docs: `octocode-documentation`

Add documentation and remove rigid or stale docs with `octocode-documentation`. It checks every command and path against the repo before writing the page.

✅ **Done when** you have the prompt review findings, a benchmark with a before/after result, a local skill that activates, and a checked `README.md`.
