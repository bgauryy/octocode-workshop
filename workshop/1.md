# Workshop 1 · Init: context awareness (10 min)

> **Before the session:** do the [Setup](../WORKSHOP.md#setup-do-it-before-the-session), so this step takes minutes and not the whole slot.

**From the slides (LLM basics):** an agent is a loop around the model, and the model sees only the context its host supplies. Tools and skills have a context cost that depends on the host and caching. A noisy harness can distract the agent and spend tokens.

## Live checkpoint

In 10 minutes, verify Octocode authentication with `npx octocode auth status`, then ask your agent one GitHub question that requires a source line, such as: “Find where zod defines `ZodObject`; cite the file:line.” Write down the citation. If authentication is missing, use **C** below. If your agent cannot list everything loaded into its context, record only what it can actually see.

**Optional after the checkpoint:** audit the full harness with **A**, then remove confirmed redundancy with **B**. Do not change shared or required tools during the timed exercise.

### A. See what your harness loaded

Paste this prompt into your running agent:

```text
List everything your harness loaded into your context for this session. Don't guess: report only
what you can see in your system prompt, tool list and loaded files.

1. MCP servers: each server name and the tools it exposes.
2. Tools: every built-in tool you can call, with a one-line purpose.
3. Skills: each skill name, its description, and the path of its SKILL.md.
4. AGENTS.md (or CLAUDE.md / other project instructions): which files were loaded, their paths,
   and a 3-bullet summary of the rules they set.
5. Anything else injected (memory, environment info, working directory, date).

End with: what looks redundant, unused or noisy.
```

### B. Remove what is redundant

Turn off the MCP servers and tools you don't need, and remove the redundant skills (two skills that do the same job, or skills you never use). Fewer tools and skills mean a smaller context and less chance the agent picks the wrong one. Restart the agent and run the prompt from **A** again to confirm.

### C. Make sure Octocode works locally (and GitHub search works)

```bash
gh auth login               # GitHub CLI: Octocode reuses it automatically
npx octocode auth login     # or the Octocode CLI: one-time browser sign-in
npx octocode auth status    # must be green
```

Then ask the agent a small GitHub question that needs Octocode, for example *"Use Octocode to find where zod defines `ZodObject`; cite the file:line."*

✅ **Done when** authentication works and you have one cited `file:line`. Record an auth or access blocker if the search cannot run.
