# 1 · Context and first citation (10 min)

**Deck section:** 01 LLM basics · **Output:** one cited `file:line` from Octocode

> **Slide recap:** an agent is a loop around the model, and the model sees only the context its host supplies. Every tool and skill costs context, and a noisy harness distracts the agent.

## Checkpoint

1. Add Octocode to your agent. Either add the stdio server to the host MCP config and restart the agent, or run `npx octocode install` to configure a detected host:

   ```json
   { "octocode": { "command": "npx", "args": ["octocode-mcp@latest"] } }
   ```

2. Sign in. Octocode reuses the GitHub CLI token when one exists.

   ```bash
   gh auth login              # or: npx octocode auth login
   npx octocode auth status   # confirms GitHub accepts the token
   ```

3. Ask your agent:

   ```text
   Use Octocode to find where zod defines ZodObject; cite the file and line.
   ```

✅ **Done when** you have one cited `file:line`, or you have written down the output of `auth status` as your blocker.

## Go further

### A. See what your harness loaded

```text
List what your harness loaded into this session. Report only what you can see in your
system prompt, tool list, and loaded files:
1. MCP servers and their tools.
2. Built-in tools, one line each.
3. Skills: name, description, SKILL.md path.
4. Project instructions (AGENTS.md, CLAUDE.md): paths and a three-bullet summary.
5. Anything else injected (memory, environment, date).
End with what looks redundant, unused, or noisy.
```

### B. Remove what is redundant

Turn off the MCP servers and tools you do not use, and remove duplicate skills. A smaller context gives the agent fewer chances to pick the wrong tool. Restart the agent and run **A** again to confirm.
