The same nine problems, now with how we resolved each one. Press → once and the rows draw in. (1) Rate limits → cache first (SHA-keyed results never refetch; others revalidate by ETag), a code-search budget of 10/min, full-jitter backoff and a circuit breaker (ledger V12–V14). (2) Leaked secrets → block credential paths and redact secrets in and out; 308 patterns in today's dev build (ledger V15; the JS layer started with 164 in v2.3.22, Jul 2025). (3) No file context → ghStructure shows the repository tree around a file at any ref (ledger V21). (4) Package names → package search resolves the name to its repository; npm_search from 1.0.0, today artifactSearch over 8 registries (packages/octocode/README.md:53). (5) Too many calls → batching, up to 5 queries per call since v2.3.27 (21 Jul 2025); measured later: 80 tool calls vs 142 for an expert gh agent on 30 GitHub questions (lean-vs-mcp-114934-2026-10-09.md:14,56). (6) Context grew → matchString fetches a window around the hit: on one 2,075-line file a full read's first page is ~19 KB, the window at 3 context lines ~3.5 KB (dev build, 2026-10-12; ledger V19). (7) Large files → minify: standard strips comments and blank lines, symbols returns an outline; the whole symbols outline of the same file is ~7.4 KB (ledger V18). (8) Large results and PRs → pagination with a next page, never a silent cut-off; the whole-response window pages at 50,000 chars (docs/OCTOCODE_TOOLS.md:16); the PR tool lists changed files first and opens only chosen patches. (9) Hallucinations → the instructions demand proof from files: "Cite source or diff lines by number; quote verbatim; never invent values." (ledger V10), and the server instruction text went from 3,807 to 1,908 chars (ledger X25). That is a size cut, not a measured hallucination rate.
