The core of the whole workshop. The brief's Octocode protocol, layer by layer as it draws top-down, and every layer is text the model reads. (1) MCP instructions frame the session (workflows and tool order): the general idea and the workflows, in XML-tagged sections (<local>, <github>, <packages>, <pages>, <evidence>…), capped at 2,000 chars because hosts truncate longer ones (docs/OCTOCODE_PROTOCOL.md:65; a code comment in packages/octocode-mcp/src/native/index.ts:289 says "near 2 KB"; ledger V10); today 1,908 chars (measured initialize.result.instructions.length on the dev build 20.2.0, 2026-10-12; the CLI prints the same text plus a <cli> line). (2) Tool description picks the tool (use when, not when): every description follows one grammar: prose (what the tool does, when it is right), an optional <empty> repair, then one <workflow> (where its output goes next) (docs/OCTOCODE_PROTOCOL.md:66). The example is the real start of localSearch's description. In full: "Find literal or regex text in local files; hits are anchors, not identity. resultView picks paths, counts, spans. <empty>Lowercase/shorter term, regex:"rust", includeIgnored.</empty><workflow>hit → localFetch; name+line → lspSearch</workflow>" (242 chars, from a live tools/list on the dev build, 2026-10-12). (3) Input schema shapes the call (goal + reason); the full row is {mainGoal, reasoning, path, matchString}: minimal fields plus optional mainGoal and reasoning for multi-call research, 1–5 queries per call (maxItems: 5 in the live tools/list; docs/OCTOCODE_PROTOCOL.md §3.4; ledger V5, V6). (4) Results steer the next step (data, pages, leads): data plus two continuation channels. next = the unread pages, hints = leads {tool, query} plus a hints.text sentence only for a per-call fact on empty rows (packages/octocode-config/contract/tool-contract.json continuationChannels; docs/OCTOCODE_PROTOCOL.md §3.8; ledger V7); the sentence shown is a real one from a live localSearch on the dev build (ledger V8). FYI, what's thin: tools/list carries only a readOnlyHint annotation per tool and no output schemas. I left the rest out on purpose to keep the context small. Main idea: give the agent the instructions and the capabilities to search smart, so it understands code from several dimensions, evidence-based.
