Without Scout, a search returns many hits and the agent reads them one by one. With Scout (Octocode docs/OCTOCODE_CLASIFY.md, measured 2026-10-08 on ast-grep): the agent sends a mainGoal ("the ast-grep code that expands a rule's fix template…"), the resources (one localSearch for "fix" in files that also mention "template", 9 files) and two questions, each one checkable fact: relevant ("builds replacement text from a fix template and matched metavariables") and sufficient ("shows where metavariables are replaced"). The Jev model scores every file against every question. All questions about one page share a single provider request, up to 25 cells per query and 50 per call (OCTOCODE_CLASIFY.md:262, :401-402). The matrix shows real numbers: template.rs relevant 0.97, sufficient 0.86. The next-best sufficient was 0.43, so every other cell in that column is at most .43 (the doc doesn't list each one). Click 1, READ: ranks 1–3, or any page with sufficient ≥ 0.7, carry hints.read, the exact read to run next (:65). Click 2, KEEP SCREENING: a high-relevant, low-sufficient page is near the answer, so read it and keep screening; a mid-band best score (about 0.4–0.7) means narrow the source or follow next.clasify (:205-216). Click 3, DEFER: low scores are deferred, never discarded ("low | defer, never discard", :277; "A low score defers a candidate; it never discards one", :344). Elimination here means not read now, not deleted. Clasify ranks attention; it never proves absence. One call, 1.9 KB, 0.7 s for 9 files; without fileHas, 54 files in 2 calls, 11.8 KB, same top two.
