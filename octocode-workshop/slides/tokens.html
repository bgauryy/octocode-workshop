A tokenizer cuts text into chunks it knows and swaps each chunk for its number in a fixed vocabulary, so the model never sees letters, only that list of IDs. The split is real: o200k_base (GPT-4o family, via js-tiktoken 1.0.21), run on 9 Oct 2026: 35 characters, 8 tokens; note "useReducer" splits into "use" + "Reducer", and the leading space belongs to the token. The IDs on screen are real too (tiktoken, o200k_base: [11437, 1919, 13886, 5391, 8844, 1199, 26828, 13]); reproduce them with enc = tiktoken.get_encoding("o200k_base"); enc.encode("Find where Next.js uses useReducer."). The vector values are illustrative. Click 3: inside the model, each ID picks one row of an embedding table, a long list of learned numbers (here the "." token, ID 13). That vector is what the model actually computes with; the Q, K and V two slides from now are made from it. The numbers on screen are illustrative; real vectors are long: GPT-3 175B uses 12,288 numbers per token (Brown et al. 2020, arXiv:2005.14165, Table 2.1; ledger B33). Each tokenizer has its own vocabulary; Claude's is not public, so use the count_tokens endpoint to measure. Why it matters: cost, limits and attention are all counted in tokens. You pay per token: Claude Sonnet 5.5 input is $2 per million, output $10 (platform.claude.com/docs/en/about-claude/pricing, 6 Oct 2026). JSON is token-hungry: Octocode's documented ghSearchCode call (docs/OCTOCODE_TOOLS.md:112, dev tree) is 66 characters, 21 tokens, 12 of them pure punctuation (o200k_base, tiktoken): 3.1 chars per token vs 4.4 for the English sentence (OpenAI's rule of thumb ~4 chars per token, help.openai.com/en/articles/4936856; ledger B2). Tokenizers change: the Claude 4.7+ tokenizer "produces approximately 30% more tokens for the same text" (same pricing page, 9 Oct 2026). Across languages, lengths differ "up to 15 times in some cases" (Petrov et al., arXiv:2305.15425). That's why Octocode strips noise from results. Next: where tokens live, the context window.
