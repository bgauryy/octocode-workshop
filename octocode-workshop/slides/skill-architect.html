The problem: agents patch locally. They fix the line in front of them and never ask what the change does to the system. This skill makes the agent model the system and prove an architectural claim before touching it. Walk the pipe: FRAME the decision, the intended benefit, the scope and the contract owner; MODEL representative flows from source through validation, transformation and boundaries to consumers; PROVE each finding with code and runtime evidence; then the GATE: "Edits authorized and seam proven?" Yes goes to CHANGE and VERIFY, no stops at "Findings + plan" (skills/octocode-architect/SKILL.md:14-20; phase table :26-32). Press → for the mechanic: "Topology edges are syntactic candidates. A type-only cycle is not runtime proof." (SKILL.md:39). So a graph edge alone is a candidate, not a defect. Extra: "Scale rigor to consequence. Do not invent layers, abstractions, findings, or operational work to satisfy a checklist." (SKILL.md:22). Topology comes from the beta npx octocode astTopology (OCTOCODE_BETA=true) or npx octocode graph (SKILL.md:8-10); the saved note has a Location / Finding / Boundary / Consequence / Confidence / Change table (output.md:32). Invoke: npx octocode skill install octocode-architect, then, for example (illustrative prompt): "Is the chrome package leaking into core? Should we split it?" Hand-off: code facts go to octocode-research; a consequential choice goes to octocode-rfc-generator for a reviewed decision record (Related skills).
