The protocol slide named the four layers; this is how they add up to one route. The instructions explain the system at the macro level: the workflows between tools, which tool comes next, and how results and hints connect one call to the next. Octocode MCP was all about context engineering: understand how an agent "sees" MCP (the server instructions once per session, the tool descriptions and schemas on every request, then the results) and use each of those to make the workflow obvious. Walk the pipe as it draws: (1) don't know the repo → ghSearchRepo, it hands over owner/repo; (2) know the repo → ghSearchCode, each hit row carries path, commitSha and line; (3) know the path → ghGetFileContent at that commitSha, the exact lines only; (4) cite the lines by number. Click 1: that route is written into the MCP instructions verbatim: "Unknown repo: ghSearchRepo. Known repo: ghSearchCode | ghStructure. Known path: ghGetFileContent at a commitSha. PR, issue, commit: ghSearchHistory → ghGetHistoryItem. Grep/AST remotely: ghStructure materialize → local tools at localPath." (<github> in the live instructions of the dev build 20.2.0, 12 Oct 2026; `octocode | jq -r .instructions`). The same instructions have the local route (<local>: Unknown path: structureSearch (names) | localSearch (text) | astSearch (syntax). Known path: localFetch. Identity: lspSearch) and a <flow> loop: "1 zoom out (tree, outline, summary); 2 search narrow (names, text, syntax, history); 3 zoom in on exact lines (matchString, ranges, block); 4 prove identity (lspSearch) and behavior (code, diffs), not names or claims; 5 cite." Click 2: the rule that keeps results thin, the end of the <flow> line: "Copy row values (path, commitSha, line, localPath); never guess." Each row carries the fields the next call needs, and nothing else; ghSearch* rows even take fields:[keys] to pick columns. Together with reasoning + goal on every call (two slides back), the agent sees the bigger picture: why it's calling, what it's looking for, and where the next hop goes. Ledger X33.
