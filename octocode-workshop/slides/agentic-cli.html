Octocode V3 · CLI

The Octocode CLI runs every tool without MCP

Install it, sign in to GitHub, call any tool from a shell, then add the skills.

npx octocode --help # runs via npx, nothing to set up
2 Authone GitHub token
npx octocode auth login # device flow; already ran gh auth login? reused npx octocode auth status authenticated as <user> (source: octocode-storage)
3 Run toolsno MCP client
npx octocode | head -c 40 # what can I call? {"kind":"octocode.toolCatalog",… npx octocode localSearch '{"path":"crates/cli","matchString":"ExitClass"}' {…"next":{"nextMatchPage":{…}}} # exit 0: run next as given

One binary, four steps, and no MCP client anywhere. Why a CLI at all? Any agent with a shell can use it, and no tool schemas sit in the context window on every turn until the agent asks for them. Every output line here is real, run on 2026-10-09 with my dev build of octocode 20.2.0 (unreleased; npm latest is 20.1.0), trimmed with …; username redacted. Step 1, install: `npx octocode` declares Node ^24.15.0 (other Node versions only print an npm engine warning); the native binary ships inside the npm package as per-platform optional dependencies (@octocodeai/octocode-native-<platform>), and the `octocode` command is a thin Node launcher over it (packages/octocode/package.json engines; packages/octocode-native/package.json:45-52; ledger W1). Press → (2), auth: if you already ran `gh auth login`, you're done. Octocode looks for a token in this order: env (GH_TOKEN/GITHUB_TOKEN, from the shell or a workspace/home .env) → encrypted ~/.octocode/credentials.json → OS keychain → `gh auth token` (docs/AUTHENTICATION.md:14-24; C3). Otherwise `octocode auth login` runs the GitHub device flow; `auth status` says where the token came from. Press → (3), run tools: a bare `octocode` on a pipe is "an agent asking what it can do" (crates/cli/src/cli/mod.rs:121-124): it prints the catalog, kind octocode.toolCatalog, every tool with its fields and the same instructions MCP sends. ` --help` ends with the required fields and one runnable example; `octocode schema --view query` prints all fields. A call is one JSON query, or up to 5 batched in {"queries":[…]}, or --input FILE|- (packages/octocode/README.md:31-32). The search above found crates/cli/src/cli/mod.rs and exited 0 with a re-runnable next.* continuation, pinned to a snapshot, so the agent never guesses page 2 (a next page is success, not an exit code: CHANGELOG.md Unreleased, "CLI paging is success; exit 6 removed"). Errors are a JSON envelope too: forget the path and you get "queries.0.path: Missing required field: path", exit 2; a typo like `localSerch` gets "similar subcommands exist: … 'localSearch'". The legend: text on a terminal, one-line JSON on a pipe (--json forces it); exit codes 0 ok, 1 empty, 2 invalid input, 3 not found, 4 auth, 5 execution, 7 rate limited (octocode --help; ledger X1, X23). In a real session that I ran, every next call was named by the previous output: catalog → error that names the fix → search with hints.read → a 1,107-byte read instead of 19,583 bytes for the file's first page. Press → (4), skills: `skill install --all --platform all` copies the 13 bundled skills once to ~/.octocode/skills, then links them into 7 agents: pi, cursor, claude, codex, opencode, copilot, gemini (packages/octocode/README.md:24,104; K3, K17); `skill list` ticks each one. If you still want MCP: `npx octocode install --ide claude-code` writes the MCP entry into one of 15 clients (--dry-run, --check, --rollback). Outside evidence for the CLI direction (vendor claims): Cloudflare, "LLMs are better at writing code to call MCP, than at calling MCP directly" (blog.cloudflare.com/code-mode, 26 Sep 2025); Anthropic, code execution with MCP "reduces the token usage from 150,000 tokens to 2,000 tokens" (anthropic.com/engineering/code-execution-with-mcp, 4 Nov 2025).
