The harness is packages/octocode-benchmark: "Every arm answers the same questions with a fresh headless agent, a blind judge grades correctness, and each agent's transcript says how many characters went through the model" (README.md:3-7). Walk the pipe as it draws (the slide keeps only the labels; say the rest): (1) 30 real GitHub research questions (canonical v2 set), refs frozen to SHAs; (2) one fresh agent per question per arm, empty working directory, no settings, CLAUDE.md, skills or memory. Arms are Octocode MCP, plain gh, a disciplined gh-lean (--json/--jq plus grep/sed -n), gh + RTK (an output compressor) and gh + Headroom (compare/arms/); (3) the judge, gpt-5.5, sees two answers as X and Y in a seeded shuffle with tool names redacted, and scores correctness 0–10 against a ground truth rebuilt with read-only gh; (4) the metric is total characters through the model (tool calls written, results read, final answer), and it only counts at equal correctness. The amber line underneath is the part that matters: read the transcripts where I lost, critique, change one thing, rerun. Press → for one real lap: the 2026-09-30 run showed "≈82% of octocode tokens are fixed overhead, not tool output": tool schemas re-sent every turn, 16,807 vs 5,029 first-request tokens, 13 MCP tools vs 1 Bash tool (.octocode/rfc/tool-improvement-2026-10/RFC.md:23-24). So the change targeted overhead: tools/list went from ≈30.1 KB (RFC.md:25, 2026-10-01) to 15,939 B for the same 13 tools (measured 2026-10-09), and OCTOCODE_DEFER_TOOLS can put rarely-used tools behind one run tool.
