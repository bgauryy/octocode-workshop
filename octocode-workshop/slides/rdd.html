MANIFEST.md:17-18: "Research Driven Development (RDD) is the methodology that formalizes 'vibe-research.' It prioritizes evidence gathering and context validation before any code is implemented… Code is Truth, but Context is the Map." (ledger V22; github.com/bgauryy/octocode/blob/main/MANIFEST.md). The picture is the manifest's adversarial flow drawn as a pipeline. Click 1: a fresh session plans. A generator (Planner) drafts, and a verifier (the manifest calls it the Discriminator) attacks it and sends flaws back, GAN-style, until the plan holds. Click 2: only plan.md crosses into a new session; the Researcher gathers evidence with the tools, and the verifier attacks every claim. Click 3: only research.md crosses into the implement session; the Coder writes code, the verifier attacks it; out comes code + tests. Click 4: each flow runs in a separate agent or session (the dashed frames), so each step starts with "the minimal context necessary for the agent to implement the task with maximum quality" (MANIFEST.md:183-190, 251-252, 361-368). Analogy: TDD for knowledge. Write the evidence first, then let a hostile reviewer attack it. The model vendor prescribes the same contract: Anthropic's "Reduce hallucinations" guide says "extract word-for-word quotes first"; "Verify with citations … If it can't find a quote, it must retract the claim" (platform.claude.com docs, fetched 2026-10-09). And what happens without it: Damien Charlotin's AI Hallucination Cases database lists 2,184 court decisions involving AI-hallucinated content, typically fake citations, as of 12 Oct 2026 (damiencharlotin.com/hallucinations).
