Why LSP. Two reasons. First, text search got noisy: as repos grew, a name matched tests, helpers, methods and substrings, and the agent read or edited the wrong code (the exit_code run on the previous slide: 26 text hits, only 4 were the function). Second, the agent needed another aspect of research: text, structure and content tell it what a thing is called, where it lives and what its lines say, but not how code connects. Press →: the four dimensions. Text finds the name (localSearch), structure finds the place (structureSearch), content reads the lines (localFetch), and the new one, connections, follows the links between symbols (lspSearch). The server instruction (ledger L2): "Identity (callers, references): lspSearch with a hit's symbolName+line." lspSearch operations (ledger L1): definition, references, callers, callees, hover, typeDefinition, implementation, workspaceSymbol, supertypes, subtypes, diagnostic, documentSymbols; language servers for TypeScript, Python, Rust, Go, Java, C/C++, C#, Scala. Measured in the scripted benchmark: "LSP references are exact (rg -w: 0.26–0.62)" (docs/OCTOCODE_PROTOCOL.md:132).
