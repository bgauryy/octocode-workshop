This is the distinction behind the skill tour. MCP supplies callable capabilities: tools/list advertises a name, description and input schema, and tools/call executes code (MCP specification, modelcontextprotocol.io/specification/2025-06-18/server/tools). A skill supplies a method for deciding what to do: the Agent Skills spec requires only SKILL.md (with name and description frontmatter) and recommends optional scripts/, references/ and assets/ folders. Its name and description (~100 tokens) are loaded at startup, the SKILL.md body when activated, and resources only when required; scripts run and only their output enters context (agentskills.io/specification; platform.claude.com/docs/en/agents-and-tools/agent-skills/overview). A skill may call Octocode through MCP or through npx octocode; when repeatable execution already has a stable CLI, use that instead of making the agent read implementation scripts. The context nuance corrects the speaker's draft: MCP is not automatically cached once for a whole session, and skills are not categorically uncached. Claude's API can cache stable tool definitions in the prompt prefix, but cache hits require an identical prefix and an unexpired cache (5 minutes by default, 1 hour optional); hosts may defer tools: the API has defer_loading, and Claude Code turns tool search on by default for MCP tools (platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool). The SKILL.md body occupies context when read; several activated skills can stack up, and that text may itself be included in a later cacheable prefix. Keep the always-visible descriptions small and put details behind the trigger.
