Why I built it, in my words: "help agent eval". The problem: "it feels better" is not evidence. This skill picks the depth of evidence the claim actually needs and guards against leakage and self-grading. Walk the pipe: Define the claim; then "Evidence needed?": a wording fix gets a review, a deterministic bug gets reproduce-and-check, and only a comparative or reliability claim takes the full path (SKILL.md:24-26); Freeze harness and baseline; Develop and select a candidate; Independent final test; Report result and limits (skills/octocode-eval-benchmark/SKILL.md:10-20). Press → for the rule: "Development iterates, validation selects, a sealed final test confirms." (SKILL.md:35), and "Repeated holdout feedback makes it development data." The solver sees only the production task; answer keys, expected tool paths and prior attempts stay out of reach (SKILL.md:33). Final verdicts are ACCEPT, REVERT, INCONCLUSIVE or INVALID; the last two prove neither failure nor improvement (SKILL.md:39). Extra: "Public fixtures, regex checks, and self-tests check the grader, never generalization" (:40). Every run is saved under .octocode/octocode-eval-benchmark/<date>-<slug>/ with dev/ and held-out/ splits, run.json and results.jsonl (benchmarks/README.md:13-24; output.md:13-17); reusable suites live in benchmarks/<name>/ (benchmarks/README.md:3-11). Invoke: npx octocode skill install octocode-eval-benchmark, then, for example (illustrative prompt): "Did my new research-skill description improve activation? Measure it." Hand-off: after an observed failure, edit instructions with octocode-agentic-prompts; skill activation questions → octocode-skills (Related skills). Next: skill 8, octocode-clean-agentic-code.
