Package search jumps from a name to its code

The agent checks the registry once, then knows which repository holds the package's code.

  1. 1

    A name in the code

    "@modelcontextprotocol/sdk"

    →a name, not a location

  2. 2

    One registry lookup

    npm search

    // repository →
    modelcontextprotocol/
    typescript-sdk

    →checked, not guessed

  3. 3

    Read the real code

    modelcontextprotocol/
    typescript-sdk · src/

    →ghSearchCode · ghGetFileContent

// one lookup; from then on the agent knows where the code lives.
The second tool goes from a package name to its code. Press → for each step. (1) While reading code, the agent sees a package name, for example an import from @modelcontextprotocol/sdk. That's a name, not a location: it doesn't say where the source lives. (2) So it checks once with npm search: the registry's repository field points to github.com/modelcontextprotocol/typescript-sdk (registry.npmjs.org/@modelcontextprotocol/sdk/latest, v1.32.1; checked for this deck). No guessing, and no hallucinated package names. (3) From then on the agent knows the repo, with the code under src/, and reads the real code with ghSearchCode and ghGetFileContent. (4) One lookup, and from then on the agent knows where the code lives. History: npm_search existed from 1.0.0 (6 Jun 2025), PyPI was added in 2.3.21, and today artifactSearch covers 8 registries: npm, PyPI, crates, Maven, NuGet, Go, Packagist, RubyGems (packages/octocode/README.md:53).
