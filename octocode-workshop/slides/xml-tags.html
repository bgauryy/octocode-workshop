The previous slide ended on the pattern the labs repeat. Here it is: two ways to structure a prompt, and why production prompts combine them. Click 1, Markdown: headings and bullets give hierarchy. Role, then rules, then a list. It's readable for you and for the model, and it's best for rules and priorities. Click 2, XML tags: they give hard boundaries. The task is in one block, the pasted files in another, so the model never mistakes your data for your instructions, and you can point at a block by name: "use only what's in context." Anthropic's prompting docs recommend XML tags for exactly this. OpenAI's GPT-4.1 guide agrees on tags for long context: "XML performed well in our long context testing" while "JSON performed particularly poorly" (developers.openai.com/cookbook/examples/gpt4-1_prompting_guide, Apr 2025). Click 3, both: this is what ships. Cursor's leaked system prompt (asgeirtj/system_prompts_leaks, Cursor/cursor.md) fences whole rule blocks in tags like <system-communication> and tells the agent which other tags carry hidden context. Octocode does the same: its MCP instructions are split into tagged blocks (<flow>, <local>, <github>, <evidence>), and its tool descriptions use Markdown inside (octocode-core src/toolContract/instructions.ts:32, TOOL_RESEARCH_INSTRUCTIONS, the text `octocode | jq .instructions` prints in the dev build; ledger X31, X32).
