Click 1: ~/.octocode is the Octocode home (%USERPROFILE%\.octocode on Windows; move it with OCTOCODE_HOME). .octocoderc = JSONC settings the MCP server and CLI read (features like local tools, tool lists, timeouts). .env = tokens and third-party API keys (GH_TOKEN, TAVILY_API_KEY, SERPER_API_KEY, EXA_API_KEY) that the CLI and MCP server load. credentials.json = encrypted GitHub login (AES-256-GCM, key in .key). skills/ = installed skills. The folder holds more than these (stats, tmp/ caches and so on), so treat the list as examples (docs/CONFIGURATION.md, docs/AUTHENTICATION.md:51, https://github.com/bgauryy/octocode/blob/main/docs/CONFIGURATION.md). Click 2: the workspace .octocode is where skills save output after you approve. The RFC generator saves <workspace>/.octocode/octocode-rfc-generator/<YYYY-MM-DD>-<slug>/RFC.md (skills/octocode-rfc-generator/SKILL.md:24); research reports and PR reviews go to .octocode/octocode-research/<YYYY-MM-DD>-pr-<number>.md (skills/octocode-research/references/workflow-pr-review.md:52); a project .env beats the home .env for the same key, except home-only keys. Click 3: results are files next to the code. Next: when both folders set the same thing, which one wins.
