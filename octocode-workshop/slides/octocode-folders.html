Click 1: ~/.octocode is the Octocode home (%USERPROFILE%\.octocode on Windows; move it with OCTOCODE_HOME), read by the CLI, the MCP server and the skills. .env holds tokens and third-party API keys: TAVILY_API_KEY, SERPER_API_KEY, EXA_API_KEY, any key your skills need, and optionally GH_TOKEN or GITHUB_TOKEN. .octocoderc is JSONC that the MCP server and CLI read: github.apiUrl points at GitHub Enterprise; local.enabled turns the local and LSP tools on (ghCloneRepo is CLI-only and needs persistent storage; the old local.enableClone key is ignored, docs/OCTOCODE_TOOLS.md:57); tools.disabled removes tools and tools.enabled is a strict allowlist; network.timeout defaults to 30000 ms (range 5000–300000). Restart the MCP server or start a new session after editing. credentials.json is the encrypted GitHub login (AES-256-GCM, key in .key); skills/ holds installed skills. The folder also holds stats and tmp caches, so treat the list as examples (docs/CONFIGURATION.md, docs/AUTHENTICATION.md:51, https://github.com/bgauryy/octocode/blob/main/docs/CONFIGURATION.md). Click 2: the workspace .octocode is where skills save output after you approve. The RFC generator writes <workspace>/.octocode/octocode-rfc-generator/<YYYY-MM-DD>-<slug>/RFC.md (skills/octocode-rfc-generator/SKILL.md:24); PR reviews go to .octocode/octocode-research/<YYYY-MM-DD>-pr-<number>.md (skills/octocode-research/references/workflow-pr-review.md:52). A project .env beats the home .env for the same key, except home-only keys. Results sit next to the code, so the next session reads them instead of redoing them. Click 3: .octocoderc never supplies GitHub tokens (docs/AUTHENTICATION.md:35); a token comes from a token variable (shell or .env), octocode auth login, or gh auth token. octocode config view opens a local settings page on 127.0.0.1 where you edit both files.
