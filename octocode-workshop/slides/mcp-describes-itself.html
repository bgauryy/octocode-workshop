The previous slide showed the conversation; this one shows what the server actually says about itself. Every piece is text the model reads, so every piece is a prompt. Click 1, instructions: one text for the whole server, returned in the initialize result. It tells the agent how to use the server: when to reach for it, in which order to call tools, what to avoid (MCP spec, lifecycle: InitializeResult.instructions, modelcontextprotocol.io/specification). Click 2, the tool definition, returned by tools/list: a name, a description that says what the tool does and when to use it, an inputSchema (JSON Schema for the arguments) and, optionally, an outputSchema for structured results (added in spec version 2025-06-18). Click 3, annotations: hints about behavior, so the host and the model know what a call will do. readOnlyHint: it only reads. destructiveHint: it may delete or overwrite. idempotentHint: calling it twice is safe. openWorldHint: it touches the outside world, like the web. They are hints, not guarantees, and clients should not trust them from untrusted servers (spec, tools: ToolAnnotations, added 2025-03-26). Click 4, the point: each tool is a bridge. On one side the agent, which only understands text; on the other side real code, a query, an API call, a file read. The description and schema are the bridge: the model fills JSON arguments, the code runs, the result comes back as text. Design the bridge well and the agent uses your code well.
