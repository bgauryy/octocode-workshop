octocode-rfc-generator

The problem: agent plans scatter across files (a plan here, KPIs there, a checklist somewhere else) and drift from the reasoning that justified them. This skill produces one reviewable document. Walk the pipe: Frame the decision; Research current state and alternatives (deciding facts verified through octocode-research, SKILL.md:30); is deciding evidence available? If not, the draft explains the unresolved choice and the next check; Write recommendation, design and plan in one RFC; Check contracts, acceptance and language, looping back to research on a material gap; then Deliver one RFC.md (skills/octocode-rfc-generator/SKILL.md:10-20). Press → for the mechanic: "One file gives reviewers a continuous argument and one diff to discuss" (SKILL.md:26), backed by "Do not generate companion plan, KPI, resource, prerequisite, audit, or receipt files" (:24). Extra: "Writing an RFC does not itself authorize implementation" (:47); sections follow Summary / Problem / Goals / Proposed design / Alternatives / Risks / Implementation & rollout / Validation / Open questions / References, modeled on the Rust RFC template and RFC Editor style (output.md:9-20; SKILL.md:43). It saves to .octocode/octocode-rfc-generator/<date>-<slug>/RFC.md, renders HTML, and replies with the HTML path for the person and the RFC.md path for agents (SKILL.md:24, :51). Invoke: npx octocode skill install octocode-rfc-generator, then, for example (illustrative prompt): "Write an RFC for moving octodeck slide order out of index.html into octodeck.json." Hand-off: structure trade-offs → octocode-architect; measurements → octocode-eval-benchmark; a settled decision becomes an ADR via octocode-documentation (Related skills).
