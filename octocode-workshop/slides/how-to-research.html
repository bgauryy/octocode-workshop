The research loop from the CLI guide — "map cheaply → search narrowly → read exact evidence → follow symbols or history" (packages/octocode/docs/OCTOCODE_CLI.md:114) — laid out per source. Press → for each lane. Local: structureSearch maps the tree; localSearch finds text, astSearch finds code shape; localFetch reads by matchString or ranges; lspSearch follows callers and references. GitHub: ghSearchRepo when you don't know the repo, then ghStructure; ghSearchCode on the default branch; ghGetFileContent by ranges ("Lean order: a ghSearchCode hit line that answers ends it; else matchString, then ranges of ≤40 lines around its hits; fullContent only for small files", ledger V11); ghSearchHistory for the PR. npm: artifactSearch gives versions, dependencies and the release source; "Registry rows are leads; read release source at its ref" — a repo link is not proof of the published version. Press → for the loop back: when a row comes back partial, next.* is "the unread rest: before claiming completeness, run it as given or narrowed, or name what stays unread"; hints.* are opt-in leads (server instructions, <pages>). Press → for the stop rule, from the server instructions' <evidence> block (ledger V10): "Cite source or diff lines by number … Stop when evidence answers; empty ≠ absent until scope, spelling, ref, index are checked." Extra: batch independent rows — up to 5 queries per call — and keep dependent probes sequential (<pages>). Keep this slide in mind when you try it on your own code.
