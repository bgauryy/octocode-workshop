Gain: fewer tokens. Price: lost comments and bodies. Map with symbols, then read exact lines before citing.
Minify is the third knob on the fetch tools, after matchString and ranges. It shrinks what travels from the source (GitHub or the local workspace) to the agent, so fewer tokens enter the context. The schema exposes it as one field, and the agent chooses it per read: minify is "none" | "standard" | "symbols" on ghGetFileContent and the local fetch tool (ledger V18; packages/octocode-tools-core/src/tools/github_fetch_content/scheme.ts and local_fetch_content/scheme.ts, z.enum(['none','standard','symbols'])). Naming check: there is no "skeleton" value; the skeleton mode is called "symbols". Click 1, none: the text as is. Secrets are still redacted. Click 2, standard: in the code's words, it "strips comments and blank-line noise while preserving indentation and code shape"; function bodies stay. The repo comments say standard is the default unless fullContent is set, which means none (fileContentProcess.ts). Recheck this against the build you demo. Click 3, symbols: a tree-sitter skeleton with an NNN| line-number gutter and no function bodies; Markdown becomes a heading outline; unsupported file types fall back to standard with a warning; matchString is ignored. Implementation: the Rust engine (packages/octocode-engine/src/bindings/minify.rs, signatures.rs). The code sample is illustrative, not real output. Click 4, the price. Measured on the same file as the previous slide (crates/runtime/src/tools/clasify/run/hydrate.rs, 2,075 lines, dev build, 12 Oct 2026): a full read's first page is 19,422 B, and the whole symbols outline is 7,412 B. I didn't measure standard, so it has no bar. The trade-off: comments often carry the why, like the rate-limit reason in the sample (bars: same 2,075-line file, bytes returned), and symbols drops behavior entirely. So minify for orientation, then fetch exact lines before citing. Next: the same choose-what-to-read idea applied to reviewing a large pull request.
