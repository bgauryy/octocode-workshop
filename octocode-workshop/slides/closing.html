Close on the spine: the model only knows what you put in front of it — so make what you put there evidence. Two things to do. One: install the research skill before you leave — the command on screen installs it for Claude Code globally (`npx octocode skill install`, ledger K3; --platform also takes pi, cursor, codex, opencode, copilot, gemini or all). Then ask it one real question about your own code and accept only answers that cite file:line — "Empty is not absent" (octocode-research SKILL.md:27). Two: audit one of your own tools against the six MCP rules from the end of Part 2 — describe when and why and name the tools before and after it; a minimal schema with an optional goal and reasoning; batch several queries per call; return windows, not files, and say what was left out; hints on empty and errors, not stack traces; small, stable instructions — Claude Code truncates server instructions and each tool description at 2,048 characters (code.claude.com/docs/en/mcp, fetched 9 Oct 2026; ledger V10). Then measure it: a fresh agent, a blind judge, characters at equal correctness. The QR goes to the repo. Then questions.
