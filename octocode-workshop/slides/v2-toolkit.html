Status check before the hands-on: this is everything Octocode gives you at the end of V2, so you know what you can call in the practice. Left, the local tools from earlier in this section: structureSearch maps the tree or finds files, localSearch finds text and regex, astSearch finds code by syntax shape, localFetch reads exact lines with matchString or ranges, and lspSearch follows definitions, references and callers (local-tools and research-dimensions slides; docs/OCTOCODE_CLI.md:114; ledger L1, L2). Turn them on with local.enabled in .octocoderc. Press →: the external tools are the same eight from the V1 toolset: seven for GitHub and npmSearch (README.md:186-223). The three opt-ins stay off until you enable them: ghCloneRepo (CLI-only by default), ghListReleases and ghSearchDiscussions (README.md:191-205). Press → again: the skills we walked through, one slide each, with research as the hub the others route code facts through (skills-intro; ledger S4, K4–K14). scraping and agents-communication also ship but are out of scope today. Install with npx octocode skill install --all --platform all. Tool names follow the dev build used throughout the deck (20.2.0); the public main README uses older names (localSearchCode, localGetFileContent, lspGetSemantics…), so check the names against your running server before the practice.
