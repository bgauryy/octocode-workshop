Octocode V2 · the config files

Keys go in .env; features go in .octocoderc

Two files in ~/.octocode: keys and tokens, switches for the tools.

TAVILY_API_KEY=… EXA_API_KEY=… SERPER_API_KEY=… # any key your skills need
→ loaded by the CLI, MCP server and skills
{ "github": { "apiUrl": "https://api.github.com" }, "local": { "enabled": true }, "tools": { "disabled": ["ghSearchRepo"] }, "network": { "timeout": 30000 } }
→ read by the MCP server and the CLI
// .octocoderc never holds tokens · edit both from one page: octocode config view
Per docs/CONFIGURATION.md (github.com/bgauryy/octocode/blob/main/docs/CONFIGURATION.md). Left: ~/.octocode/.env holds third-party API keys: TAVILY_API_KEY, SERPER_API_KEY, EXA_API_KEY, and any other keys your skills need. The CLI and the MCP server load it too, and it can also hold GH_TOKEN or GITHUB_TOKEN. Press → for the right file: ~/.octocode/.octocoderc is JSONC, read by the MCP server and the CLI. github.apiUrl points at GitHub Enterprise. local.enabled turns local + LSP tools on; ghCloneRepo is CLI-only and needs persistent storage, the default; the old local.enableClone key is unknown and ignored (docs/OCTOCODE_TOOLS.md:57). tools.disabled removes tools; tools.enabled is a strict allowlist. network.timeout defaults to 30000 ms (range 5000–300000). Restart the MCP server or start a new session after editing. Press → for the rule: .octocoderc never supplies GitHub tokens (docs/AUTHENTICATION.md:35); a token comes from a token variable (shell or .env), octocode auth login, or gh auth token. octocode config view opens a local settings page on 127.0.0.1 where you edit both.
