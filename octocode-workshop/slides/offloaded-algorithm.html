These three were the main tools, the core of how I researched code by hand: (1) search repositories, which is how I pick the right repo; (2) find the correct places in a repo; (3) read a file by its content and its relations to other files. Press → for each step; each card draws in and says what it hands to the next step. In full: which repositories matter (keywords, owner, stars, activity) → owner/repo; which paths and files inside it hold the answer → path + line; what the file says and what it imports and calls → lines + links. Today they are named ghSearchRepo, ghSearchCode and ghGetFileContent (packages/octocode-config/contract/tool-contract.json; ledger V21); in 1.0.0 (6 Jun 2025) they were search_github_repos, search_github_code and fetch_github_file_content (36f55ae3c:src/tools/contstants.ts:2-15). Other tools came later as usage grew, such as ghStructure for the tree around a file and the npm tool; we'll meet them in the "Octocode in scale" section.
