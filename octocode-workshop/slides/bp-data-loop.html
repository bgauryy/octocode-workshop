Three habits for the data side of a tool. Press → (ask): give the agent the ability to ask for data in any permutation. Filters combine freely: ghSearchRepos takes keyword, owner, topic, language and stars; ghSearchCode searches code or paths; and each call batches 1 to 5 queries, each with its own filters (README.md:186-223; v1-tools slide). The agent shapes the question; the tool doesn't force one path. Press → (paginate): always think of the context window. Large results come in pages with a next page, never a silent cut-off; the whole-response window pages at 50,000 characters (docs/OCTOCODE_TOOLS.md:16). The PR tool pages files, comments and commits (filePage, commentPage, commitPage). And zoom in: on one 2,075-line file a full read's first page was ~19 KB, the matchString window ~3.5 KB (dev build, 2026-10-12; ledger V19). Press → (reflect and benchmark): after a task, ask the agent which call was wasted and which hint it skipped; test cold with a fresh, small model; then measure against the strongest baseline you can build, like gh-lean in October. The callback: clasify was offered in 30 of 30 sessions and called 0 times (results/mcp-clasify-ab-111154-2026-10-09.md:8-15; ledger X10). Only the benchmark showed it.
