LLM basics

An agent loops around the model

It connects model responses to tool calls and feeds the results into the next turn.

What the model sees: just text, start to end
[system + tools] user: fix the login bug → call search("login") ← result: auth.ts:42 …
What the agent adds: the loop
  1. 1

    model reads

    the whole stream

  2. 2

    asks for a tool

    name + JSON args

  3. 3

    your code runs it

    search · read · test

  4. 4

    result appended

    as more text

repeat until done
Two ideas only. First: the model never sees "tools" or "files"; it sees one stream of text, from the system prompt and tool schemas, through the user's request, to every tool call and every result, in order. It predicts what comes next. Press → for the second idea: an agent is the loop around that model. The model reads the stream, asks for a tool by name with JSON arguments, your code runs the tool, and the result is appended to the stream as more text. Then the model reads it all again, until it's done. So your tool's output is literally part of what the model reads next. Source: Anthropic, "Building Effective Agents" (19 Dec 2024, anthropic.com/engineering/building-effective-agents): "Agents … are systems where LLMs dynamically direct their own processes and tool usage."
