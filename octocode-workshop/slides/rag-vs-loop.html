My pick: the loop. It felt right (it is how I research), and for me it was cheaper.

Click 1: the RAG pipeline draws top-down: index first, ask later (crawl and chunk, index, retrieve, hand top-k to the model). RAG (Lewis et al. 2020, arXiv:2005.11401) pairs a model with a retrieval index: parametric plus non-parametric memory. Sparse retrieval matches exact terms (BM25); dense retrieval uses learned embeddings (DPR, Karpukhin et al. 2020, arXiv:2004.04906). For code my problems were exactly the red lines: chunks lose the file and how it connects; dense misses exact identifiers, sparse misses meaning; and every index goes stale on the next commit. And it is one shot: the model gets whatever top-k returns. Click 2: the loop searches the live code instead: plan, search the live code at any ref, read only the window around the hit, take the hint, plan again. People told me loops (repeated tool calls) were wasteful. Click 3: the honest pros and cons. RAG's plus: one fast lookup that finds code by meaning; Cursor measured "on average 12.5% higher accuracy" (6.5–23.5% by model) when semantic search is added to grep, and "the combination of these two leads to the best outcomes" (cursor.com/en-US/blog/semsearch, 6 Nov 2025); and Oskooei et al. found semantic search answered 65.2% vs 46.2% for subagent agentic search at under half the cost on read-only Q&A (arXiv:2608.01507, 2 Aug 2026), a different setup from a main agent with hints. RAG's minus: an index to build, store and keep fresh. The loop's plus: no index, always the current code at any ref, and it follows names and hints across files. The loop's minus: more calls, more latency and re-read tokens. Cherny himself called the early evidence "mostly vibes" and said agentic search costs latency and tokens (latent.space/p/claude-code, 7 May 2025). The Claude Code team still landed on the loop: "Early versions of Claude Code used RAG + a local vector db, but we found pretty quickly that agentic search generally works better. It is also simpler…" (Boris Cherny, x.com/bcherny/status/2017824286489383315, Feb 2026). Also in the loop camp: Cline ("when you chunk code for embeddings, you're literally tearing apart its logic", 27 May 2025), the OpenAI Codex prompt ("prefer using rg or rg --files"), Sourcegraph Cody (its Feb 2024 blog: "we're leaving them [embeddings] behind (for now)"; sourcegraph.com/blog/how-cody-understands-your-codebase). Click 4: my pick: the loop. It felt right, because it is how I research, and for my use it was cheaper: no index to build or keep fresh (my own experience, not a benchmark). An index is a tool, not the architecture. Measure, don't believe. The rest of V1 is about making each lap cheap. Each web source is named inline above (fetched 2026-10-09).
