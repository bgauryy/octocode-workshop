The map to keep in mind for everything that follows (ledger V21, S3; packages/octocode-config/contract/tool-contract.json; docs/OCTOCODE_MCP.md "Tool catalog"). The families draw left to right. GitHub: ghSearchRepo (repositories), ghSearchCode (indexed code, default branch), ghStructure (a tree at any ref; it can materialize files for the local tools), ghGetFileContent, ghSearchHistory (PRs, issues, commits) and ghGetHistoryItem (read one); ghCloneRepo is CLI-only. Local: structureSearch, localSearch, astSearch, localFetch; astTopology and astRewrite are CLI-only betas behind OCTOCODE_BETA. LSP: lspSearch, real language servers. Packages: artifactSearch across 8 registries — npm, PyPI, crates, Maven, NuGet, Go, Packagist, RubyGems (packages/octocode/README.md:53). Remote: clasify, a semantic judge from an external provider (vendor: Jev) that needs a classification key — without one MCP leaves it out (docs/OCTOCODE_TOOLS.md "Internal, external, and hybrid tools"). Counts: "16 tools. Your agent gets 12 tools over MCP and 13 in the CLI; clasify joins both when you add its key" (README.md:124). Press → for the foundation they all stand on: "Every tool takes up to 5 queries per call" (docs/OCTOCODE_MCP.md); mainGoal and reasoning per row; next.* is the unread rest and hints.* are opt-in leads (docs/OCTOCODE_PROTOCOL.md:88-93); the native secret scanner reads every byte bound for the model; and the CLI's exit codes are a typed control channel — 0 ok, 1 empty, 2 invalid input, … 6 partial: run next (packages/octocode/README.md "Output and exit codes"). Names changed over versions — V1 had snake_case names like search_github_code — but the contract stayed. The boxes pair the tools by job: GitHub find (repo, code), read (structure, file), history (search, item); local find (structure, text), syntax + read (AST, fetch), and the CLI-only betas. Cut from the slide: GitHub covers repos, code, tree and PRs; local covers text, tree, syntax and reads; clasify joins both MCP and the CLI once its key is set.
