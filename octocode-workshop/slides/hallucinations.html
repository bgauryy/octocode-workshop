The last row of the problems table: hallucinations, meaning confident claims with no line behind them. Stronger wording alone did not fix it, so we changed what the agent is asked to do with every answer: prove it from files and validate everything. Left side, condensed from the live server instructions (dev build 20.2.0, 2026-10-12; ledger V10, X33). Full wording: "Cite source or diff lines by number; quote verbatim; never invent values." Click 1: "prove identity (lspSearch) and behavior (code, diffs), not names or claims". A matching name is not proof; the definition and the diff are. Click 2: understand connections. Before claiming how code works, the agent follows the real links with LSP: where a symbol is defined, who calls it, what imports it. Click 3: "Empty ≠ absent until scope, spelling, ref, index are checked." An empty search is not evidence that something does not exist. Click 4: check the next step. The tool schemas carry this: descriptions say when to call a tool, an empty block says how to repair a miss, and a workflow block names the next hop, so the agent verifies before it answers (docs/OCTOCODE_PROTOCOL.md:66, ledger M4). Also in the instructions, if asked: "Copy row values (path, commitSha, line, localPath); never guess." Anthropic's hallucination guide gives the same advice: "Verify with citations … If it can't find a quote, it must retract the claim." Click 5, the other half of the fix: shrink the text that describes the MCP, because it is sent on every request and competes with the evidence for attention.
