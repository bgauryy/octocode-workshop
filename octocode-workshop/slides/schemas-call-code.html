Schemas let the LLM call real code

The model reads only the schema, writes a valid call, and deterministic code does the work.

{ "name": "get_time", "description": "Current time in a timezone", "input": { "tz": { "enum": ["UTC", "Asia/Jerusalem"] } }, "output": { "time": "string" } }
get_time({ "tz": "Asia/Jerusalem" })

The previous slide ended on structure inside prompts. Schemas took that structure one step further: they let the model talk to code, in a predictable way. The point: a schema is the contract of a function, written so the model can read it. The model never sees the function body; it reads only this. Click 1: the schema. A name, a description, a typed input and a typed output. The description string IS the prompt the model reads when it decides to call and fills the arguments. The enum removes a whole class of invented values: the model can only pick a listed timezone. The output tells it what comes back, so it can read the result and plan the next step. A vague schema gets invented arguments; a typed schema gets reliable calls. Quote to say aloud: Anthropic, "Writing effective tools for agents" (anthropic.com/engineering/writing-tools-for-agents, 11 Sep 2025): "Even small refinements to tool descriptions can yield dramatic improvements"; "think of how you would describe your tool to a new hire on your team". Their later tool-use examples raised accuracy "from 72% to 90% on complex parameter handling" (anthropic.com/engineering/advanced-tool-use, 24 Nov 2025). Click 2: the model doesn't run anything. It writes a call, valid JSON that matches the schema, here get_time with a timezone. Click 3: your code runs it. That part is deterministic: same input, same output, no guessing. A model can't know the current time; a clock function can. Click 4: the result goes back into the context window, and the model answers from real data instead of predicting it: the time, a web search, a file, a database query. Clicks 5 to 7: where it led (ledger H6). June 2023, OpenAI function calling (gpt-4-0613): the model returns a JSON object with the arguments and the developer's code calls the function (openai.com/blog/function-calling-and-other-api-updates, 13 Jun 2023). The catch: every integration was built again, custom per model and per app. 25 Nov 2024, Anthropic publishes the Model Context Protocol, one protocol for tools and the subject of the MCP arrival section (anthropic.com/news/model-context-protocol). 26 Mar 2025, OpenAI adopts MCP, so the rival lab joins (simonwillison.net/2025/Mar/26/openaidevs). Click 7: 9 Dec 2025, MCP is donated to the Agentic AI Foundation under the Linux Foundation (anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation). Once every tool is described by a schema, any agent can call any tool the same way. We come back to how MCP works later.
