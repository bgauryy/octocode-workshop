A large PR can have dozens of files and hundreds of comments; dumping all of it into context buries the change that matters (the same lost-in-the-middle problem). So ghSearchPullRequests works like a reviewer, step by step. Step 1: get the overview: metadata, body and the changed-file list, paged with filePage and itemsPerPage. The agent looks at the file names and decides what is worth checking. Click 1: open patches only for the chosen files: content.patches.mode is "none", "selected" or "all", with patches.files naming the files (or patches.ranges for specific lines). The code on the right is a schematic call; the PR number and path are made up. Click 2: read the discussion selectively: content.comments has discussion, reviewInline, includeBots and a per-file filter, paged with commentPage. You also choose body, changedFiles, reviews and commits (list, includeFiles). reviewMode "full" turns everything on: all patches, comments, reviews and the commit list, so use it only on small PRs. Click 3: paginate everything: filePage, commentPage, commitPage, itemsPerPage, and charOffset/charLength for long bodies. Then verify outside the diff: ghGetFileContent for the surrounding code, and ghSearchCommits for history or a diff between two refs. Sources: bgauryy/octocode packages/octocode-tools-core/src/tools/github_search_pull_requests/scheme.ts, splitSchemes.ts and contentRequest.ts (PrContentSelector). Parts of the schema come from @octocodeai/octocode-core/schemas, so check the field names against the running server before presenting.
