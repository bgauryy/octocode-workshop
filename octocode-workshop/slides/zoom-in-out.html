The "context grew" fix as a picture. Left: one file drawn as a strip of lines (a drawing, not the real file). Click 1, zoom out: search returns the path and the hit line (green), no body. Click 2, zoom in: matchString with contextLines fetches just a window around the hit (white bracket; its bar is the cyan one below); everything else stays out of the context, and the result marks the gaps as "… [lines A-B not requested] …" (crates/runtime/src/tools/numbered.rs:81-86). Click 3, widen only on purpose: ranges (up to 10), block (the hit's whole declaration, ≤400 lines: BLOCK_MAX_LINES in local_fetch/block.rs:10), or minify "symbols" for an outline (ledger V18). The tool descriptions teach this order. ghGetFileContent, live on the dev build: "Read a GitHub file at a ref: matchString windows, ranges, a named declaration (matchString+block), or a minify:"symbols" outline. A path alone: first 50 lines of a file over 16 KiB; fullContent: all." And ghSearchCode: "A hit line can be the answer." (`octocode schema ghGetFileContent`, 2026-10-12; ledger V11). The bars are measured (re-measured 12 Oct 2026 with the dev build's local CLI, bytes of JSON output, rounded; the first run on 9 Oct used an earlier copy of the file): crates/runtime/src/tools/clasify/run/hydrate.rs, 2,075 lines / 85 KB on disk, matchString "MAX_HYDRATED" with 11 hits. contextLines 0 = 1,037 B, 3 = 3,514 B, 10 = 7,734 B; a full read's first page alone = 19,422 B; the whole symbols outline = 7,412 B. So the new default of 3 is about −55% vs the old 10, and about −80% vs the full read. The repo has an older, different measurement in a code comment: "A default read cost 4.9 KB at 10 and 1.3 KB at 2" (octocode-core 20.0.1, dist/toolContract/limits.js:71; ledger V19). The default is now 3 (contextLines: "default 3" in the live schema), changed from 10 on 2026-10-09. History: partial reads (startLine/endLine) landed on 5 Jul 2025 (commit 4a31fd816, "support partial fetching") and shipped in 2.3.10 on npm on 6 Jul 2025; matchString in 3.0.0 (27 Jul 2025). Honest caveat from the October benchmark: agents set contextLines themselves in 31 of 32 reads. The real cost is whole-file reads and wide windows, which is why the description teaches the order. Outside evidence that agents over-read: ContextBench (1,136 tasks, 66 repos): "LLMs consistently favor recall over precision" and "substantial gaps exist between explored and utilized context" (arXiv:2602.05892, 5 Feb 2026).
