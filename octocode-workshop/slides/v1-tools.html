Octocode in scale · the toolset

Eight tools cover GitHub and npm research

Each tool handles one research step: find the source, locate the code, read it, then check its history.

Locate the code

Read it

The full external toolset in one view: eight tools registered by default, seven for GitHub and one for npm, grouped by the research step they serve. Start left: find the source. ghSearchRepos finds repositories by keyword, owner, topic, language or stars; npmSearch resolves a package name to its source repository, which fixed the "hard to find where a package lives" problem. Click 1, locate: ghSearchCode searches code and paths, batching 1 to 5 queries per call; ghViewRepoStructure shows the tree around a file (the structure view from earlier). Click 2, read: ghGetFileContent reads a whole file, a line range, a matchString window or paginated characters, with an optional minifier. That is the zoom in and zoom out. Click 3, history: ghSearchPullRequests searches PRs or opens one in depth (files, patches, reviews, commits); ghSearchIssues does the same for issues and their comments; ghSearchCommits walks history or compares two refs, optionally with the diff. Click 4: three more are off unless you enable them with an environment flag: ghCloneRepo (ENABLE_CLONE, supports a sparse subtree), ghListReleases (ENABLE_RELEASES) and ghSearchDiscussions (ENABLE_DISCUSSIONS); on MCP those last two must also be listed in ENABLE_TOOLS (README.md:191-205). Sources: bgauryy/octocode main, README.md:186-223 and packages/octocode-tools-core/src/tools/toolConfig.ts; packages/octocode-tools-core/src/tools/toolNames.ts. Tool names are taken from the README; the string constants live in @octocodeai/octocode-core, so check the names against the running server before presenting.
