With the environment in place, my recommendation is to let the agent run the tests itself, in a loop. Give it the test command and let it write, run, read the failure, fix and rerun until green, instead of you copying errors back into the chat. The important part is TDD. Look at the loop on the left: red, the agent first writes a test that fails for the behavior you want; green, it changes the code until that test passes; refactor, it cleans up while the tests stay green. The test becomes the spec the agent works toward, and the loop tells it when it's done. The second important part: remove junk tests. Agents happily generate rigid tests: hand-picked inputs that just mirror the implementation, exact string and snapshot matches, call counts on internal functions, mocks that only test the mock. They break on every harmless change, and then the agent spends its loop "fixing" tests instead of code, or bends the code to satisfy them. Delete those and keep the tests that check behavior a user would notice. This is my recommended practice, not a measured result. Next: research before you write the code.
