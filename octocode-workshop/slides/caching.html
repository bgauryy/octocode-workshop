LLM basics

Prompt caching reuses the prefix

The provider keeps the prefix's keys and values so later messages can reuse that work.

New tokens: read for the first time, full price.

Cached tokens: their K and V are saved, not the text, and reused at 0.1× or less.

Default cache: 5 min idle, then it expires; each hit resets the clock. Change an early word: miss too.

Link back: on the last slide the model kept K and V while writing one answer. Prompt caching keeps them between your messages. The model keeps no memory between messages: every time you send a message, the app re-sends the whole conversation (tools, instructions, every earlier message and reply) plus the new one. The provider has already computed the K and V for the start of that conversation, so it keeps them. OpenAI: "The prompt cache stores key-value (KV) tensors, not the tokens themselves" (developers.openai.com/api/docs/guides/prompt-caching). Anthropic: "KV cache representations and cryptographic hashes are held in memory for the cache TTL and promptly deleted after expiry" (platform.claude.com/docs/en/manage-claude/api-and-data-retention). That gives two kinds of input tokens. New tokens are read for the first time at full price. Cached tokens are the prefix whose K and V are already saved. Click 1: message 1. Everything is new and full price, and the provider saves it (writing the cache costs a little more: 1.25× for the 5-minute cache, 2× for the 1-hour cache; ledger B7). Click 2: message 2 re-sends all of message 1 and the reply. That part is cached, plus the new message. On Anthropic, cache reads cost 0.1× base input on most models (0.05× on Opus/Sonnet 5.5; ledger B7). Example: Claude Sonnet 5.5 input is $2 per million tokens and cache reads are $0.10, the 0.05× rate; on Sonnet 5 the same $2 input reads at $0.20, the standard 0.1× (platform.claude.com/docs/en/about-claude/pricing and prompt-caching docs, checked Oct 2026). The slide says "0.1× or less" to cover both. Click 3: message 3. The cached part keeps growing and the new part stays small, which is why long agent loops are affordable. Click 4: the cache expires. Anthropic's default cache lives 5 minutes and every hit refreshes it; a 1-hour option has a higher write price (ledger B7). Walk away for coffee and the next message re-reads everything at full price. It also misses if anything near the start changes, because each token's K and V depend on every token before it: "Cache hits require 100% identical prompt segments" (platform.claude.com prompt-caching docs). OpenAI works the same way: caching is on by default from 1,024 tokens, and "the entire rendered prefix" must match (ledger B8). It's faster too: a 100K-token cached prompt went from 11.5 s to 2.4 s to first token (claude.com/resources/articles/prompt-caching, the page Anthropic's 14 Aug 2024 announcement now lives at; the same-day coverage is simonwillison.net/2024/Aug/14/prompt-caching-with-claude; ledger B11). Manus called cache hit rate "the single most important metric for a production-stage AI agent", with cached input at 0.30 vs uncached at 3 USD/MTok (ledger B11). Caching discounts input only; output is billed normally. Rule for tool builders: put stable things first and changing things last, so no dates or random ordering in instructions.
