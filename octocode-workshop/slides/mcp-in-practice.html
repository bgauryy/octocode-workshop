Everything on this slide is real. Install (README.md:62-63): in Claude Code, `claude mcp add octocode --scope user -- npx -y octocode-mcp@latest`; for any other client, `npx octocode install --ide <id>` writes the server entry into that client's config — `octocode install --list` shows 15 client ids: cursor, claude-desktop, claude-code, windsurf, trae, antigravity, vscode-cline, vscode-roo, vscode-continue, zed, opencode, gemini-cli, kiro, codex, goose (live run, 2026-10-09); `--dry-run` shows what it would write first. Auth: GH_TOKEN/GITHUB_TOKEN, `octocode auth login` once, or the `gh auth token` fallback (docs/OCTOCODE_MCP.md:26). What the agent sees before any call: 12 tools by default — 13 when a clasify key is set (README.md:124) — and server instructions of 1,669 characters, under the 2,000-character cap because hosts truncate near 2 KB (documented for Claude Code: 2,048 chars for server instructions and for each tool description, code.claude.com/docs/en/mcp) (live initialize, 2026-10-09; docs/OCTOCODE_MCP.md:57). In September 2026 the instructions were 3,807 chars and tools/list plus instructions ~81k chars; today tools/list is ~16.5k chars for 13 tools (planning notes at commit 17375b97a, lines 5-12; live run) — different measurement methods, so read it as a trend. Right: a real tools/call over stdio on 2026-10-09, trimmed to fit (the hit file is crates/cli/src/cli/mod.rs; full: mainGoal "How does the CLI map error classes to exit codes?", plus reasoning, path, pageSize, matchPageSize). Click 1 — hints.read is an optional lead: the cheapest next read, already written as a localFetch call with ranges around both hits. Click 2 — next.nextMatchPage is required: the response is incomplete without it, and the query is pinned to a snapshot so page 2 matches page 1.
