Why this matters: the agent loop re-sends the whole window on every request (system prompt, every tool definition and every earlier result), so a byte you cut is a byte you stop paying for on every later turn. The repo's own finding: "≈82% of octocode tokens are fixed overhead, not tool output" (.octocode/rfc/tool-improvement-2026-10/RFC.md:23). Each bar is one mechanism, after ÷ before on the same input; the coloured part is what's kept, the dashed part is what got cut. The three layers, said aloud: every request: tool schemas are re-sent on every turn; every result: minimal unless the agent asks for more; every read: windows, not files. Step 1, every request: deferring rarely-used tools (OCTOCODE_DEFER_TOOLS) replaces 9 tool schemas with one run({tool, query}) dispatcher: 10,865 → 1,805 bytes, measured 2026-10-09 on the core dist's published schemas (docs/generated/CONFIG_SETTINGS.md:84; a test asserts the dispatcher is under half: src/__tests__/surfaceArms.test.ts:76-82). Slim published schemas: tools/list was ≈30.1 KB on 2026-10-01 (RFC.md:25) and is 15,939 B for 13 tools now (measured 2026-10-09). Step 2, every result: minimal by default, extras are opt-in. ghSearchCode is 2,257 B by default vs 4,674 B with everything on (.octocode/rfc/tool-quality-efficiency-2026-10/research/meaningful-output.md:33-55); prose hints only on empty or failed rows, one tip ≤120 chars, so a not-found row went 306 → 187 B (docs/TOOL_DATA_CONTRACT.md:32,90-91; TOOLS-END-TO-END.md:72); ghSearchHistory pages went 30 → 10 rows because "a 30-row page cost ~7.8 KB where shell agents read 10–15 rows" (toolContract/limits.ts:42-47). Step 3, every read: a matchString window on an 11-hit, 2,097-line Rust file (crates/runtime/src/tools/clasify/run/hydrate.rs) is 3,749 B vs 19,438 B for just the first page of the whole file, re-measured 2026-10-09 with the local CLI; contextLines default 10 → 3 the same day: 7,974 → 3,749 B on that read (limits.ts:88-94: agents set it themselves 12 of 12 times and answers sat within 1–3 lines); minify:"symbols" on a 471-line TypeScript file (packages/octocode-mcp/src/native/index.ts): 19,729 → 2,767 B, measured 2026-10-09. Honest caveats: the October transcripts say wide windows and whole-file reads, not the default, were the real lever; and a symbols outline can still lose bytes to a plain grep of def/class lines, though it wins on coverage. Why deferral matters outside Octocode too: Anthropic counted 5 MCP servers = "58 tools consuming approximately 55K tokens before the conversation even starts"; their Tool Search cut that by 85% and raised Opus 4 from 49% to 74% (anthropic.com/engineering/advanced-tool-use, 24 Nov 2025). Claude Code now defers MCP tools once their definitions pass 10% of context (code.claude.com/docs/en/mcp). Next: the workbench every change is built in.
