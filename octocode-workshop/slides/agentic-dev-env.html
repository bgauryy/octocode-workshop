This is a general way to set up a local dev environment so an agent can work in any repo. The problem: AI tends to generate a lot, and it quickly becomes hard to follow, so the repo has to tell the agent where everything is. Read it top to bottom, the way the agent does. CLAUDE.md is the entry: tiny, it just says "Read AGENTS.md". AGENTS.md is the map: short, it says where things are and links to them instead of repeating them. Everything it links lives in a folder: docs/ holds all the documentation (architecture, packages, guides), so AGENTS.md just points there; .agents/skills/ holds the repo's skills, shared ones plus project-specific workflows, so they load the same way; .octocode/ (git-ignored) keeps the reports, plans and gotchas the agent writes back. Short entry files, detail in folders. In the Octocode repo this is exactly the layout (repo read 2026-10-10; ledger X35, X36). Next: with the environment in place, let the agent loop on tests.
