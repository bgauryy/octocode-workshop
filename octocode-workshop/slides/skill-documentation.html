The problem: agent-written docs invent commands that don't exist and drift from the code. This skill verifies every claim against the repo and applies a real style guide. Walk the pipe: UNDERSTAND the deliverable, audience and approved paths; RESEARCH: verify commands, paths, APIs, env vars and behavior in the repo; CLASSIFY: one mode per target: agent-docs (AGENTS.md, CLAUDE.md), human-docs (README, how-to, API docs, runbook), adr, codebase-pack (one page per package) or style-pass (wording only) (SKILL.md:28; references/modes.md:12); WRITE, with an outline when useful; STYLE, then VERIFY: a fact change or a gap loops back to RESEARCH (skills/octocode-documentation/SKILL.md:8-14). Press → for the rule: "Take commands only from manifests, Makefiles, or CI; never invent scripts." (SKILL.md:21). Extra: it has the largest reference set of any skill, 12 files and 727 lines, including a local Google word list (assets/google-word-list.tsv) and optional STE-80 controlled English (SKILL.md:40, :55-68). An ADR is only for a choice that is already decided; an open choice goes to octocode-rfc-generator (SKILL.md:33). Shipped docs are edited at their own path; reviews go to .octocode/octocode-documentation/ (SKILL.md:79). Invoke: npx octocode skill install octocode-documentation, then, for example (illustrative prompt): "Update the README install section and check it against the CLI." Hand-off: command and API facts → octocode-research; instruction wording that changes agent behavior → octocode-agentic-prompts (Related skills). Next: octocode-roast, the blunt one.
