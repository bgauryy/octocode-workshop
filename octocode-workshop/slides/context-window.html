The model has no memory between calls: every turn, the whole array is sent again. That means the system prompt, the MCP server's instructions, every tool's name, description and schema, then all messages and tool results so far. Left side, what's in it. The first blocks are a real measurement: Octocode's own benchmark probe found 16,807 tokens in the first request with its 13 MCP tools, against 5,029 with a single Bash tool. That 13 is the set the probe measured (Sep 2026), not the tool count on the what-is-Octocode slide: today's dev default is 12 MCP tools, 13 with clasify; the exact count moves with the build; "≈11.8k extra tokens re-sent on every request" (octocode repo, .octocode/rfc/tool-improvement-2026-10/RFC.md:24, probe results/dedup-20260930, Sep 2026). Point to the search call and its 20 hits with line numbers. Then show the cost of "read the whole file" (1,200 lines, most of it noise), and how the free space at the bottom shrinks. Block heights are illustrative, not measurements (ledger D1). Next click: how big the window is depends on the model. GPT-4o 128,000 (developers.openai.com/api/docs/models/gpt-4o); Claude Opus/Sonnet/Haiku 5.5 1M (platform.claude.com/docs/en/about-claude/models/overview); Gemini 3.1 Pro 1,048,576 input tokens (ai.google.dev, gemini-3.1-pro-preview); GPT-6 Astra 1,050,000 (developers.openai.com/api/docs/models/gpt-6-astra); Llama 4 Scout "up to 10M" per Meta, many hosts serve less (dev.meta.ai/llama/models/llama-4); re-checked Oct 2026 (ledger B3). Last click: bigger isn't sharper. NoLiMa (Adobe, arXiv:2502.05167, 7 Feb 2025): "We evaluate 13 popular LLMs that claim to support contexts of at least 128K tokens … At 32K, for instance, 11 models drop below 50% of their strong short-length baselines"; GPT-4o fell "from an almost-perfect baseline of 99.3% to 69.7%" (often misquoted as "10 of 12"). Chroma's LongMemEval run: focused prompts of ~300 tokens scored significantly higher than the full 113k-token input (trychroma.com/research/context-rot, 14 Jul 2025). Claude's own docs: "more context isn't automatically better. As token count grows, accuracy and recall degrade, a phenomenon known as context rot" (platform.claude.com/docs/en/build-with-claude/context-windows, 9 Oct 2026) (ledger B4). Extra fact: in Octocode's clasify A/B run, 30 questions delivered 313,115 characters of tool output, yet the Sonnet worker consumed 2.26M input tokens including cache (packages/octocode-benchmark/results/mcp-clasify-ab-111154-2026-10-09.md); that multiplier is the re-sending. Tool-builder lesson: your results stay in the window for every later turn, so size them like they'll be paid for again and again. Next: how the model actually reads this window: Q, K and V.
